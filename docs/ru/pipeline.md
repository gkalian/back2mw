# Алгоритм работы

Как проходит один прогон `back2mw`. Стадии, инварианты, точки отказа.

---

## Развёртывание у пользователя

Один исполняемый файл в своей папке, **не внутри установленной игры**:

```
<папка с back2mw>/
  back2mw
  config.toml        пути, выбранные плагины, смещение, язык — переживает переустановку
  sources/           сюда пользователь кладёт моды и плагины Oblivion/Skyrim
```

Рабочие файлы лежат **в корне игр**, в папке `_back2mw-output` (не в `Data` / `Data Files`, не в `%TEMP%`):

```
<Oblivion>/_back2mw-output/            распакованные BSA, кеши. Большое и выбрасываемое
<Morrowind>/_back2mw-output/output/    готовые к установке мод и архивы
<Morrowind>/_back2mw-output/stage/     подготовка установки; стирается после неё
```

Больше ничего программа не пишет: ни в `%TEMP%`, ни в профиль пользователя, кроме `config.toml`
(рядом с программой или в `%LOCALAPPDATA%\back2mw`, если туда нельзя писать). Пути можно переопределить
ключами `work_dir`/`output_dir`.

Почему не в `Data Files`: менеджеры модов считают её своей территорией. И главное — **рабочие
данные не должны попадать в `Data Files`**, потому что и
игра, и Construction Set сканируют эту папку, а распакованные BSA Oblivion это гигабайты
`.nif` и `.dds` с чужими путями.

Нулевая настройка достигается автообнаружением: Morrowind через реестр
`HKLM\SOFTWARE\Bethesda Softworks\Morrowind` → `Installed Path` плюс `Morrowind.ini`;
Oblivion и Skyrim так же; библиотеки Steam через `libraryfolders.vdf`. Не нашлось —
спрашиваем один раз и пишем в `config.toml`.

Установка в `Data Files` — **отдельное явное действие** с манифестом записанного, чтобы
можно было откатить. Никогда не неявно.

## Стадии

Одна подкоманда на стадию плюс `all`. Каждая читает результат предыдущей с диска, поэтому
любую можно перезапустить отдельно.

!!! note "Что из этого уже есть"
    Отдельной командой сейчас запускаются `all`, `validate`, `package`, `install`, `uninstall`.
    Стадии от `discover` до `write` выполняет `all` за один прогон (в журнале каждая строка
    начинается с имени стадии); по отдельности они не запускаются.

**Стадия, для которой в источнике нет материала, просто пропускается.** Это не особый режим,
а нормальное поведение: прогон только по моделям не задействует `world`, `faces` и `audio`,
и именно так выглядит первый рабочий результат.

| Стадия | Что делает |
|---|---|
| `discover` | Находит установки, перечисляет плагины источника. **Если в источнике есть ландшафт** — сканирует целевой load order и вычисляет смещение |
| `extract` | Распаковывает нужные BSA источника в `work/`, кеш по манифесту. Читатель BSA v103 свой (`tes4_read::bsa`): `tes3::bsa` умеет только формат TES3 |
| `read` | Разбирает плагин источника в типизированную модель |
| `transform` | ID из FormID, типы объектов, статы NPC, характеристики предметов (цены — как в Oblivion или, по галочке, подтянутые к Morrowind), пути к ассетам |
| `world` | Слияние 2×2, сшивка `LAND`, применение смещения, размещения |
| `meshes` | NIF 20.0.0.4/20.0.0.5 → 4.0.0.2 (основная версия Oblivion — 20.0.0.4, см. [formats/nif-oblivion.md](formats/nif-oblivion.md)). **Текстуры не конвертируются, а копируются** рядом с новой моделью: Morrowind понимает DDS Oblivion. Переносятся только слоты, выжившие при переносе `NiTexturingProperty` — base и glow; нормали и спекуляр в ванили не используются. Пути переписываются, коллизии имён при уплощении дерева разводятся детерминированно |
| `creatures` | Свои модели существ без донора: скелет, части тела и клипы папки → три файла на модель (`<имя>.nif`, `x<имя>.nif`, `x<имя>.kf`); записи с одним набором частей делят модель. Существо, чья модель не собралась, в плагин не идёт |
| `faces` | Запекание `EGM`/`EGT` с коэффициентами NPC → уникальные головы и текстуры, дедупликация одинаковых наборов |
| `audio` | Звуки `SOUN`: `.wav` из BSA, стерео сводится в моно своим кодом (`mesh_convert::audio`); голоса — mp3, склеиваются по кадрам (`mesh_convert::audio::mp3`). ffmpeg не нужен — форматы Oblivion и Morrowind совпадают |
| `write` | Пишет `.esp`/`.esm`, раскладывает ассеты |
| `validate` | `esmtool dump` по плагину, `niftest` по каждому мешу. Любая найденная ошибка валит прогон. **Критерий у инструментов разный:** у `esmtool` — код возврата, а `niftest` всегда возвращает 0, и ошибку видно только по строкам `Failed to read` в stderr (измерено) |
| `package` | loose-файлы или BSA, zip готового мода |

## Выбор смещения

!!! note "Что из этого уже есть"
    Сейчас смещение по умолчанию ставит мир восточнее ванильных земель (западный край на x = 32,
    южный на y = −19), моды в `Data Files` не учитываются. Своё смещение — флаг `--offset`, ключ
    `offset = [dx, dy]` в `config.toml` или галочка в окне; консоль и окно читают один и тот же
    ключ. Сканер занятых ячеек и автоматический выбор свободного места (пункты 1–3) ещё не
    сделаны.

Нужен только когда в источнике есть ландшафт. В TES3 нет worldspace: один экстерьер с
координатами ячеек в `int32` — практически бесконечный — плюс интерьеры.

1. **Сканируем целевой load order.** Читаем `[Game Files]` из `Morrowind.ini` **и вдобавок
   все `.esm`/`.esp`, физически лежащие в `Data Files`.** Не только активные: игрок может
   включить Tamriel Rebuilt позже, а смещение к тому моменту уже запечено. Собираем занятые
   внешние ячейки по `gridX`/`gridY`.
2. **Выбираем свободный прямоугольник** под габариты worldspace плюс зазор.
3. **Сообщаем решение и его основание:** какое смещение и какие диапазоны заняты кем.
4. **Override** — пользователь может задать своё; мы только проверяем, что не налезает.
5. **Смещение фиксируется навсегда** после первой установки: оно запечено в координаты ячеек
   и через них в сохранения. Пишется в `config.toml`; при обнаружении нового соседа молча
   **не двигаем**, а сообщаем и требуем явной переконвертации.

Никакого чекбокса «сместить» нет: смещение нужно всегда, потому что окрестности начала
координат занимает Вварденфелл. Вопрос только в величине, а её мы вычисляем.

Применение смещения — чистая арифметика: `gridX`/`gridY` в `CELL.DATA` и `LAND.INTV` плюс
`dx`, `dy`; мировые X/Y размещений плюс `dx*8192`, `dy*8192`; Z и координаты внутри ячейки
не трогаются.

### Тематический конфликт решению не поддаётся

Province: Cyrodiil **уже является** Сиродилом. Двух Сиродилов в одной игре быть не может,
сколько бы километров сетки между ними ни лежало. Максимум: заметить такой плагин и
предупредить. Выбор — за игроком, и притворяться, что мы его решаем, вредно.

## Инварианты

**Детерминированность.** Одинаковый вход → побайтово одинаковый выход. Без неё не работают
ни кеш, ни защита сохранений. Поэтому строковые ID **вычисляются** из FormID, а не выдаются
счётчиком, и любой обход коллекций упорядочен.

**`validate` — часть потока, а не ручной шаг.** Ванильный движок брак не показывает: объект
просто не появляется, и причину узнать нельзя. Значит брак ловится до игры.
При этом зелёный `niftest` не отменяет проверки в самой игре — там, где OpenMW мягче ванили
(снятые лимиты, автогенерация коллизии при отсутствии `RootCollisionNode`), он скажет «ок»
на том, чего ванильный движок не покажет.

**`tes3conv` независимым оракулом не является.** Он построен на том же `Greatness7/tes3`,
которым мы пишем, поэтому round-trip через него проверяет только правильность использования
API. Остаётся полезен как читаемый дифф против **ванильных** плагинов.

**Один плагин источника — один плагин Morrowind** с тем же именем (T1.15). Плагины не
сливаются: у игрока каждый мод включается и выключается сам по себе. Меши, текстуры и иконки —
общие папки; для BSA — свой архив на каждый плагин (`Mod1.bsa`).

**Только добавление.** Ни одна ванильная запись Morrowind не переопределяется. Мастером
остаётся `Morrowind.esm` плюс DLC, если ссылаемся на их содержимое.

**MGE XE ни на что не влияет.** Distant Land — это LOD, косметика на стороне игрока.
Конвертация полна и корректна без него.

## Повторные прогоны и сохранения

| Изменение | Сохранения |
|---|---|
| исправление меша, текстуры, коллизии | выживают |
| смена схемы путей мешей и иконок (T1.14) | выживают: ссылки идут по ID, а не по пути |
| правка таблиц в `data/` | выживают |
| смена схемы вывода ID | **ломаются** |
| смена смещения | **ломаются** |

Это должно быть в changelog каждой версии. Референс здесь ограничивается предупреждением,
что у него FormID меняются между версиями; у нас ломается только перечисленное и только по
явному действию.
