# SpeedTree `.spt` (SpeedTreeRT 4.x) в Oblivion

Деревья `TREE` ссылаются на `.spt` в `trees\` архива мешей. Это **параметры генератора**, а не
меш: дерево строит движок SpeedTreeRT, статически слинкованный в `Oblivion.exe`. План
переноса — [Деревья](../types/tree.md).

Источники фактов: `anahuj/spttools` (`FORMAT`, реверс редактора) и записи реверса
`bryantmh/tes4skyrim` (`docs/commentary/asset_convert_speedtree.md`). Лицензий у обоих нет —
здесь только факты, пересказанные и проверенные на наших файлах; непроверенное помечено.

## Поток тегов

Файл — последовательность «тег `u32` LE + значение», без размеров и без вложенности на уровне
байтов (блоки обозначены парами маркеров). Тип значения определяется тегом:

| Тип | Раскладка | Примеры тегов |
|---|---|---|
| маркер | нет данных | `1002`/`1003` ствол и ветки, `1004`/`1005` листва, `1016`/`1017` уровень, `1007`/`1008` карта листвы, `12000`/`12001` коллизия |
| байт | 1 | `2002`, `6015`, `6016`, `15002`, `4000` |
| целое | `i32` | `1014` число уровней, `2005` семя, `6008`/`6009` сегменты, `16003`, `16013` |
| `f32` | 4 | `2006` размер, `2007` разброс размера, `6010`…`6014` |
| `N × f32` | `4N` | `4001`/`4004`/`4005`/`4006` (3), `12002` сфера (4), `12003` капсула (5), `12004` коробка (6), `8003`/`8005`/`8009` материалы (13), `20005` (8) |
| строка | `u32` длина + байты | `1000` сигнатура `__IdvSpt_02_`, `2000` кора, `4003` листва, сплайны `6000`…`6007`, `6017` |
| прямоугольники | `u32` N + `N × 8 × f32` | `10002`…`10004` (сводная текстура) |

Полная таблица — `mesh_convert::speedtree::kind`. Неизвестный тег — ошибка: пропустить его
нельзя, и единственная проверка таблицы — поток кончается ровно на последнем байте.

**Измерено 2026-09-26** (`mesh_convert/tests/real_speedtree.rs`): все 139 `.spt` (113 в
`Oblivion - Meshes.bsa`, 26 в `DLCShiveringIsles - Meshes.bsa`) разобраны до последнего байта;
встречается 165 разных тегов, наибольший — `22000`. Блока `7000` (листья-билборды) и коробок
коллизии (`12004`) в игре нет; сферы и капсулы — у 9 деревьев, 18 объектов.

## Сплайн Безье

Строка вида

```
BezierSpline <min> <max> <разброс>
{
	<N>
	<x> <y> <dx> <dy> <длина касательной>   × N
}
```

`y` кривой отображается в `min…max`, разброс — случайная добавка. Числа — текст, экспонента
бывает с тремя цифрами (`-6.24607e-008`). Разобраны все 4 860 сплайнов (139 деревьев × уровни
× 9 слотов). Как кривая вычисляется — T2.4b, **не проверено**.

## Модель (`speedtree::model`)

- **Глобальное:** `2000` текстура коры (путь редактора, `C:\…\*.tga` — в игре текстура берётся
  по имени), `2005` семя (у всех 139 ненулевое — генерация воспроизводима), `2006` размер (от 11
  до 600, медиана 150; единицы — футы SpeedTree, в игре ×10 по записям референса, **не
  проверено**), `2007` разброс размера.
- **Уровни:** `1014` — их число (3 у 22 деревьев, 4 у 111, 5 у 6), затем по блоку `1016…1017` на
  уровень: девять сплайнов (`6000` возмущение, `6001` гравитация, `6002` гибкость, `6003`
  профиль гибкости, `6004` длина, `6005` радиус, `6006` профиль радиуса, `6007` начальный
  угол, `6017` профиль гравитации), `6008`/`6009` сегменты по кругу и по длине, `6010`…`6012`
  окно и частота рождения детей **следующего** уровня, `6013`…`6016` тайлинг коры. Последний
  уровень — уровень листвы: `6004` там — расстояние размещения, часть полей не используется.
- **Наборы на уровень вне блока:** `15002`/`15003` (случайный сдвиг V, скрутка) и
  `16002`…`16012` (упаковка сегментов, вздутия) идут по одному набору на уровень, в порядке
  уровней; число наборов равно числу уровней у всех 139 файлов. Вздутия есть у 73 уровней.
- **Листва:** `3007` допуск размещения, `3008` столкновения (0 нет, 1 ветка, 2 дерево); карты
  `1007…1008`: `4003` текстура, `4004` начало, `4005` размер / 100, `4006` — по реверсу
  выводится движком из `4005`. Карт у дерева 0…6 (у 73 деревьев — 4).
- **Коллизия:** `12002` сфера (центр, радиус), `12003` капсула (центр, радиус, длина), `12004`
  коробка (два угла).

## Генератор случайных чисел (сверено с кодом, 2026-09-27)

Проверено дизассемблером по `Oblivion.exe` Steam (`mesh_convert/tests/disasm_speedtree.rs`;
адреса — VA, база `0x400000`). Реализация — `speedtree::rng`.

- **Ядро** `0x7a6cd0`: Park–Miller «minimal standard», `a · 16807 mod (2³¹ − 1)` по схеме Шраге
  (деление на 127 773 через магическое умножение `0x834E0B5F`), неположительное — `+ (2³¹ − 1)`.
  Текущее значение — целое в `f64` (`0xb42c90`). Выход: целое округляется до `f32`, умножается на
  `1/(2³¹ − 1)` (`f64` `0xa89c50`), результат снова `f32`.
- **Засев** `0x78ea30` → `0x7a6d30`: семя `max(n, 1)` (−1 — по времени, у игры не встречается);
  128 последовательных значений ядра заполняют таблицу (`0xb42a90`), текущим остаётся последнее.
- **Выдача** `0x7a6fd0` (`Random01` — `0x78e990`): Bays–Durham, индекс `trunc(ядро · 128)`,
  отдаётся ячейка, на её место — следующее значение ядра.
- **`RandomRange(lo, hi)`** `0x78ea00`: `f32(lo + r · (hi − lo))`. Поток один на всё: объект в
  `ecx` у вызывающих разный, но функция берёт глобальное состояние.

## Вычисление сплайна (сверено с кодом, 2026-09-27)

Реализация — `speedtree::spline`. Сплайны кэшируются по тексту (`0x786c60`), таблица строится
один раз.

- **Управляющие точки** (`0x7860d0`): направление касательной нормируется (`0x78e6a0`, нулевое
  не трогается), длина абсолютная; отрезок `P_i → P_{i+1}` — кубический Безье с управляющими
  `P_i + длина_i·d_i` и `P_{i+1} − длина_{i+1}·d_{i+1}`.
- **Точка кривой** (`0x7844a0`): `t` зажимается в `0…1`, `u = t·(n − 1)`, отрезок `i ≤ u < i+1`,
  де Кастельжо (`0x783e70`) по `u − trunc(u)`, промежуточные — `f32`; `u ≥ n − 1` — последняя
  опорная точка; при `n ≤ 1` — ноль.
- **Таблица** (`0x786350`), 500 записей по 24 байта (`y` на +4): кривая в 500 точках `t = i/500`;
  `table[0]` и `table[499]` — первая и последняя из них (`t = 499/500`, **не** конец кривой);
  `table[k]`, `k = 1…498`, — при `x = k/500` линейно между соседними точками кривой (поиск
  вперёд от прошлого отрезка).
- **Вычисление** (`0x784210`): `i = trunc(x·499)`, шаг таблицы считается `1/499` (`0xa8b9f8`),
  хотя строилась она с шагом `1/500`; `i = 499` — последняя запись. Итог — `min + (max − min)·y`
  плюс `RandomRange(−разброс, +разброс)`, **число из генератора берётся всегда**, даже при нулевом
  разбросе.
- Рядом (около `0x7843a0`) есть второй вычислитель: ближайшая запись `trunc(x·499 + c)` и разброс,
  пропорциональный `y`. Кто его зовёт — разбирается в T2.4c.

Все 4 860 сплайнов игры — из двух и более точек, таблицы конечны на всей сетке
(`real_speedtree.rs`). Одноточечный сплайн у движка дал бы 0/0 — так же и у нас.

## Ствол и ветки (сверено с кодом, 2026-09-27)

Реализация — `speedtree::branch`. Построитель ветки — `0x7925b0`, дерево — `0x7a45f0`,
сечение — `0x78feb0`. Геометрия коры совпадает с движком: число вершин и веток у всех
четырёх деревьев, снятых референсом с настоящего движка, — точно (`treeenglishoakforest01su`
10 019, `treedogwoodsu` 2 403, `dbush03` 558, `treeginkgo` 2 035 вершин / 66 веток;
`real_speedtree_branches.rs`). Все 139 деревьев строятся, числа конечны, вершин меньше 65 536
(наибольшее — 56 355 у `treeenglishoakunique01su`).

**Точность.** x87 во время `Compute` считает с точностью 24 бита: каждая операция округляется до
`f32`. В двойной точности у гинкго `15 / size · length` = 5.99999987 → 5 веток вместо 6 (и 53
ветки вместо 66). Поэтому вся арифметика — в `f32` по операциям, в порядке движка.

**Размер и семя (код игры).** Размер `2006` и разброс `2007` умножаются на настройку
`fTreeSizeConversion` (10) — `0x560789` → `SetTreeSize` `0x78b0e0`. Функция `0x7871d0` —
не размер, а дистанции LOD (`fTreeNearDistanceBase` 2048, `fTreeFarDistanceBase` 16384). Семя
экземпляра передаёт игра: ссылка с `XSED` — `SNAM[XSED mod n]` (`0x4ba060`), без `XSED` —
`SNAM[rand() mod n]` генератором игры (`0x4ba2a0`: вариант меняется от загрузки к загрузке),
`SNAM` пуст — 0 (семя по времени). Семя, не равное 0 и 1, заменяет `2005` (`0x7a24f0`).

**Дерево** (`0x7a45f0`): `Seed(семя)`; размер = `RandomRange(size − var, var + size)`;
`srand(16013)` — вздутия берут числа из CRT `rand()` (`state·214013 + 2531011`, 15 бит);
`Seed(семя)` ещё раз; ствол: счётчик = семя, позиция 0, единичная матрица, ось `(0, 0, 1)`.

**Ветка** (`0x7925b0`), по порядку чисел:
1. вздутия уровня (`0x791e80`, `rand()`): начальный угол, на каждое — смещение, ширина влияния
   (градусы → радианы), дальность по длине, радиальная дальность;
2. длина = `length(x)·size`, азимут = `RandomRange(−180, 180)`, начальный угол, гравитация,
   радиус = `radius(x)·size`, гибкость (только ветер); `x` — позиция на родителе,
   нормированная по окну рождения родителя;
3. повторы текстуры: `V = v_abs ? v_tile : length/size·v_tile`, `U = u_abs ? u_tile :
   u_tile·радиус·2π` (радиус до ограничения); скрутка меняет знак при нечётном счётчике;
4. `radius_profile(0)·радиус` не больше `0.85 ·` радиуса родителя в точке крепления, иначе
   радиус = это значение;
5. кольца `n = 6009 + 1`; кольцо 0: два значения возмущения (второй вычислитель, см. выше),
   поворот вокруг оси родителя на азимут, поворот двумя углами (начальный угол + возмущение),
   изгиб гравитацией; кольцо `i`: `t = pow(i/(n−1), 16002)`, радиус по профилю, изгиб, два
   значения возмущения, шаг вдоль направления прошлого кольца;
6. изгиб: угол `a` между направлением и `(0, 0, −1)`, `w = 1 − |90 − a|/90`,
   `угол = (−2·(gravity_profile(t) − 0.5))·гравитация·a·w`, ось — `dir × G`, умножение справа;
7. сечение: `cross + 1` вершин (шов), нормаль `cos θ·строка1 + sin θ·строка2`, радиус
   `· (1 + Σ вклад вздутий)`, `UV = (доля·U + скрутка·t, −V·(t + сдвиг))` — V переворачивает
   `SetTextureFlip(true)` игры; нормали пересчитываются по соседним вершинам (`0x78f7a0`);
8. дети (если следующий уровень — не листва): `trunc(freq/size·length)`; на каждого —
   счётчик `+= 3` и засев им; позиция `RandomRange(first, last)`, у первого — в окне
   `0.85…0.95`; точка по длине дуги (`0x78f720`; за концом — отрезок 0 с экстраполяцией, как у
   движка); засев ещё раз и одно пустое число `RandomRange(0, 100)`.

Вздутие (`0x78f2c0`): `(1 − |Δθ|/влияние)^rexp · радиальная дальность · ((L − t)/L)^lexp`
при `|Δθ| < влияние` и `t < L`, иначе 0.

Не переносится: ветер, LOD, касательные для нормалмапов. На вырожденных кольцах (радиус 0)
движок получает NaN в нормалях — у нас там нормаль сечения. **Не проверено** в игре.

## Листва (сверено с кодом, 2026-09-27)

Реализация — `speedtree::branch` (листья) и `speedtree::cards` (карточки). Число листьев совпадает
с движком у всех деревьев, снятых референсом: гинкго 470, кизил 1 203, дуб
`treeenglishoakforest01su` 572, `dbush03` 100, тополь 250; у `dtree01/02/04/10` и
`treekvatchburnt` листьев нет, как и у движка.

**Лист — «ребёнок» последнего уровня веток** (построитель переходит на путь листа, если
следующий уровень — последний). На лист: позиция на ветке `RandomRange(first, last)` без засева;
в `0x7920a0` — дистанция `length_листвы(xnorm) · size / 6009_листвы` (не меньше 0.01), азимут
`RandomRange(−180, 180)` вокруг оси ветки, наклон 60° вокруг локальной Y (`0x78eec0`), центр =
точка на ветке + направление · дистанция; нормаль — от кольца 0 предка на `3001` уровней выше.

**Запись** (`0x7919d0`): карты раскладываются в два списка (`0x791870`): карта `i` даёт записи
`2i` и `2i + 1` (вторая — зеркальная), в список цветения (`4000` = 1) или обычный. Цветение
(`0x78f600`, только при непустом списке цветения): позиция (`xnorm` листа, при `3001` = 0 —
позиция ветки на родителе) больше `3000` и `RandomRange(0, 1) ≤ 3002`; вопреки записям
референса, эти теги работают (карт цветения в игре 10). Выбор записи — `trunc(RandomRange(0, 10⁵
или 10⁶)) mod n`. Столкновения (`3008`: 1 — с листьями той же ветки, 2 — всего дерева): лист
отклоняется, если по всем трём осям строго ближе `3007 · max(ширина, высота карты)`. Принятый
лист тянет ещё `RandomRange(0, 10000)` (индекс угла ветра) и разброс цвета.

**Карточки.** У движка лист — билборд, углы от камеры считаются каждый кадр, статичной геометрии
нет. У нас — крест из двух вертикальных плоскостей: размер `4005 · size · 10` (размер без
разброса), точка крепления `4004` в центре листа, UV — прямоугольник карты из `10002` (у 127
деревьев из 139; у остальных — текстура целиком), V перевёрнута; поворот креста вокруг
вертикали — от числа ветра (наш выбор). **Не проверено** в игре.

## NIF дерева (T2.4f, 2026-09-27)

Реализация — `speedtree::nif`. Кора — треугольники из полос веток, текстура
`textures\trees\branches\<имя из 2000>`; листва — карточки с альфа-тестом (порог 128), обе
стороны отдельными треугольниками (двусторонность стенсилом в ванильном Morrowind не проверена),
текстура — `ICON` записи `TREE` из `textures\trees\leaves\`. Коллизия — только ствол (полоса
первой ветки) в `RootCollisionNode`; объекты коллизии `.spt` (`12002…`, у 9 деревьев из 139, у
капсул нет ориентации) не переносятся. Формы делятся по 65 535 вершин и треугольников.

Все 139 `.spt` (семя самой `.spt`, `real_speedtree_nif.rs`): `niftest` — 0 отказов;
треугольников коры 1 106 868, листвы (с обратными сторонами) 392 696; все текстуры коры и листвы
есть в архивах. LOD нет: самые густые деревья — около 110 тыс. треугольников.

## Запись `TREE` в конвейере (T2.4g, 2026-09-27)

`TREE` → `STAT` (`transform::objects`, тип в `MODEL_RECORDS`). `MODL` записан относительно
`Trees\` с ведущим `\` (`\Dbush16.spt` → в архиве `trees\dbush16.spt`, в `Oblivion - Meshes.bsa`,
не под `meshes\`). Стадия мешей строит NIF генератором, а не конвертирует (`pipeline::tree_one`).

**Семя экземпляра у движка** (`0x4ba060`, `0x4ba2a0`): у ссылки с `XSED` (extra-данные типа
`0x38`) — `SNAM[XSED mod n]`; без `XSED` — `SNAM[rand() mod n]`, заново при каждой загрузке; `SNAM`
пуст — 0, и тогда берётся семя `.spt` (0 и 1 движок семенем не считает).

`Oblivion.esm` (2026-09-27): семян в `SNAM` у записей — 0: 2, 1: 83, 4: 4, 5: 49, 6: 3, 7: 1 (итого
у 57 из 142 записей по 4–7 вариантов). Ссылок на `TREE` во всём файле 141 612, с `XSED` —
129 262; значения `XSED`: 0 — 86 150, 1 — 13 917, 2 — 13 837, 3 — 7 991, 4 — 5 935, прочие —
единицы и десятки.

**Варианты.** Каждое семя — другое дерево, поэтому у записи столько `STAT`, сколько семян в
`SNAM` (пуст — один, с семенем `.spt`). Первый вариант получает ID записи
(`ob_<EDID>_<base36(FormID)>`), вариант `k ≥ 1` — производный ID `obt<k>_…`
(`ids::variant_id`, тот же механизм, что у левой перчатки и частей тела `BODY`). Ссылка берёт
вариант `XSED mod n`, как движок (`XSED` — первый байт поля); без `XSED` — `FormID ссылки mod n`
(у движка случайно при каждой загрузке, у нас — чтобы прогоны совпадали; **наш выбор**). Путь
меша — `transform::tree_mesh_path`: хеш от `.spt`, семени и листвы.

`Oblivion.esm` (2026-09-27, `back2mw/tests/statics.rs`): 142 записи → 371 вариант, 370 разных
мешей (у одной записи семя повторяется), 139 `.spt`; ID все разные, самый длинный — 31 знак;
`esmtool` читает все 371. У 26 деревьев `SEWorld` — по одному семени, варианты там не возникают.
